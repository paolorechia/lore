# Lore's vision

Status: bootstrap knowledge distilled from the project handover.
Scope: project.
Sources: [source record](../../docs/bootstrap-sources.md), README sections 1–6 and 29–30.

Lore preserves what a team knows about its software: domain rules, architecture, conventions, rationale, exceptions, and lessons from failed approaches. Humans and teams maintain that knowledge; agents help realize it as code.

The knowledge belongs to the project and team, independently of any agent or session. Code remains important evidence. The proposition that more implementation can become derived is a research hypothesis.

Ask: **If the implementation were deleted and regenerated, would we want this information to survive?**

The project is a public exploratory monorepo. Optimize for useful experiments and small composable primitives. Local open-source core comes first; a commercial multiplayer platform is a possible future direction.

Lore is its own first test repository. Success means a fresh agent can use relevant accumulated knowledge to avoid repeated mistakes with less human correction. More generated code or more stored notes alone does not demonstrate success.
